# Яндекс.Музыка → YouTube Music

CLI для переноса и регулярной синхронизации плейлистов Яндекс.Музыки в
YouTube Music. Ищет каждый трек, проверяет, что запись действительно
добавилась, сохраняет состояние для продолжения с места остановки и складывает
отчёты для ручного разбора спорных совпадений.

Версия 0.2.0. Нужен Python 3.10+.

## Что изменилось в 0.2.0

- Неоднозначные совпадения (`ambiguous`) **по умолчанию пропускаются**, а не
  добавляются наугад. Включить их можно флагом `--add-ambiguous`.
- Добавлен `review.html` — локальная страница, где можно выбрать кандидата или
  вставить свой `video_id` и выгрузить `decisions.csv`.
- Появились `--resume`, `--retry-missing`, кэш поиска и офлайн-повтор
  (`--reuse-cache`).
- Синхронизация нескольких плейлистов через TOML-конфиг (`--config`).
- Запись в YouTube Music проверяется: ошибка API больше не считается успехом,
  после добавления состав плейлиста перечитывается.
- Матчинг стал строже: транслитерация кириллицы, штрафы за каверы, live-версии,
  другого исполнителя и слишком далёкое название.
- Пакет устанавливается как `yandex2ytm` (см. `pyproject.toml`).

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Либо как пакет с консольной командой:

```bash
pip install -e .
yandex2ytm --version
```

Без установки пакета скрипт запускается напрямую:
`python yandex_to_ytmusic.py --help`.

## Авторизация

### Яндекс.Музыка

1. Откройте <https://music.yandex.ru> и войдите в аккаунт.
2. DevTools → Network → фильтр Fetch/XHR, обновите страницу.
3. Откройте запрос к `api.music.yandex.*` → Request Headers.
4. Скопируйте `Authorization` без префикса `OAuth `.

Токен передаётся через `YANDEX_MUSIC_TOKEN`, `--yandex-token` или
`--yandex-token-file`. Он нужен для «Мне нравится», своих и приватных
плейлистов. Не коммитьте токен в репозиторий.

### YouTube Music

Предпочтительный способ — OAuth:

```bash
ytmusicapi oauth
```

Результат (`oauth.json`) передайте через `--ytm-auth oauth.json` или
переменную `YTMUSIC_AUTH`. Можно положить файл рядом со скриптом — он будет
найден автоматически (сначала `oauth.json`, затем `browser.json`).

`ytmusicapi browser` тоже поддерживается, но в новых версиях библиотеки этот
способ считается устаревшим, а скопированные заголовки быстрее истекают.

Проверка авторизации без переноса:

```bash
export YANDEX_MUSIC_TOKEN="..."
yandex2ytm --check-auth --ytm-auth oauth.json
```

## Быстрый старт

Пробный прогон: только поиск и отчёты, плейлист не создаётся.

```bash
yandex2ytm \
  --yandex-playlist "https://music.yandex.ru/users/username/playlists/3" \
  --dry-run \
  --max-tracks 10
```

Полный перенос:

```bash
yandex2ytm \
  --yandex-playlist "https://music.yandex.ru/users/username/playlists/3" \
  --ytm-auth oauth.json \
  --name "Мой плейлист" \
  --privacy PRIVATE
```

Поддерживаются ссылки:

- `https://music.yandex.ru/users/<user>/playlists/<kind>`
- `https://music.yandex.ru/playlists/<uuid>`
- `owner:kind` (например, `ivan:3`)
- просто `kind` — для плейлиста своего аккаунта
- `--liked` — коллекция «Мне нравится»

## Разбор спорных совпадений

Каждый прогон создаёт каталог (по умолчанию `runs/<дата-время>`):

| Файл | Назначение |
| --- | --- |
| `report.csv` | все треки, статусы, оценки по компонентам, топ кандидатов |
| `candidates.csv` | кандидаты в длинном формате, удобно фильтровать |
| `decisions.csv` | шаблон ручных решений |
| `review.html` | локальная страница выбора кандидатов |

Порядок работы:

1. Запустите перенос с `--dry-run` (или обычный, если готовы к записи).
2. Откройте `review.html` (двойным щелчком, без сервера).
3. Для спорных треков выберите кандидата, вставьте свой `video_id` или
   отметьте «пропустить».
4. Нажмите «Скачать decisions.csv» и положите файл в каталог прогона.
5. Повторите запуск с `--resume` — решения применятся, поиск уже найденных
   треков не повторится.

В `decisions.csv` используются колонки `key` (или `position`),
`chosen_video_id` и `action`:

- `action=skip` — исключить трек;
- `chosen_video_id=<id>` — добавить выбранный ролик;
- пустой `action` с `chosen_video_id` — то же, что выбор вручную.

`decisions.csv` можно править и вручную. Ошибочный `video_id` не ломает
прогон: трек получит статус `error` с пояснением в `note`.

## Состояние и кэш

Состояние по умолчанию: `.yandex2ytm/<источник>.json`, путь можно задать
флагом `--state`. Оно хранит найденные совпадения, `target_playlist_id` и
позволяет продолжить прерванный прогон:

```bash
yandex2ytm ... --resume
yandex2ytm ... --resume --retry-missing   # повторить not_found/error
```

Кэш поиска: `.cache/yandex2ytm` (`--cache-dir`). Повторный прогон не ходит в
поиск за теми же запросами:

```bash
yandex2ytm ... --dry-run --reuse-cache    # только кэш, без сети
yandex2ytm ... --refresh-cache            # игнорировать и обновить кэш
yandex2ytm ... --no-cache                 # не использовать кэш
```

`--reuse-cache` (он же `--offline`) полезен, чтобы после ручной правки
штрафов/порогов и `--resume --retry-missing` пересчитать совпадения без
обращений к YouTube.

## Синхронизация существующего плейлиста

Дополнить существующий плейлист:

```bash
yandex2ytm ... --playlist-id "PLxxxxxxxx" --update --resume
```

Удалить из цели треки, которые ранее переносились, но теперь исключены
(`skip`, `not_found`, `duplicate`):

```bash
yandex2ytm ... --playlist-id "PLxxxxxxxx" --update --remove-missing --resume
```

Удаляются только `video_id`, известные из состояния этого источника, — чужие
треки в плейлисте не затрагиваются. Повторный запуск идемпотентен: уже
имеющиеся `video_id` не добавляются второй раз.

## Перенос по конфигу

`sync.toml`:

```toml
[defaults]
privacy = "PRIVATE"
min_score = 0.72
delay = 0.3
out = "runs"            # общий каталог, внутри — подпапка по name

[[sync]]
name = "Rock"
source = "https://music.yandex.ru/users/user/playlists/3"
target = "PLxxxxxxxx"   # необязательно: дополнять существующий плейлист
playlist_name = "Rock from Yandex"

[[sync]]
name = "Liked"
source = "liked"
playlist_name = "Liked from Yandex"
# out = "runs/liked"    # точный каталог для этой записи
```

Запуск:

```bash
yandex2ytm --config sync.toml --ytm-auth oauth.json
yandex2ytm --config sync.toml --only Rock --dry-run
```

Для каждой секции состояние и `decisions.csv` разделяются суффиксом имени,
если заданы `--state`/`--decisions`. `[defaults].out` и `--out` задают общий
каталог, `out` внутри `[[sync]]` — точный каталог этой записи. Сводка по всем
секциям пишется в `--json-summary`.

Поддерживаемые ключи секции: `name`, `source`, `target`, `playlist_name`,
`description`, `out`, `min_score`, `search_limit`, `alternatives`,
`allow_videos`, `add_ambiguous`, `delay`, `privacy`, `cache_dir`,
`retry_missing`, `remove_missing`, `language`, `location`, `proxy`.

## Флаги

| Флаг | Значение |
| --- | --- |
| `--yandex-playlist` | ссылка/идентификатор плейлиста |
| `--liked` | перенести «Мне нравится» |
| `--yandex-token`, `--yandex-token-file` | токен Яндекса |
| `--ytm-auth` | `oauth.json` или `browser.json` |
| `--check-auth` | проверить авторизацию и выйти |
| `--name`, `--description` | название и описание нового плейлиста |
| `--privacy` | `PRIVATE` (по умолчанию), `UNLISTED`, `PUBLIC` |
| `--min-score` | порог совпадения, по умолчанию `0.72` |
| `--search-limit` | сколько результатов учитывать, по умолчанию `10` |
| `--alternatives` | сколько кандидатов сохранять в отчёты, по умолчанию `3` |
| `--allow-videos` | искать в видео, если среди песен нет уверенного совпадения |
| `--add-ambiguous` | добавлять неоднозначные совпадения (по умолчанию пропуск) |
| `--skip-ambiguous` | устарело: ambiguous и так пропускаются |
| `--max-tracks N` | обработать только первые N треков |
| `--dry-run` | только поиск и отчёты |
| `--out DIR` | каталог прогона |
| `--resume` | продолжить по сохранённому состоянию |
| `--retry-missing` | при resume повторить `not_found`/`error` |
| `--state FILE` | путь к файлу состояния |
| `--playlist-id ID` | целевой плейлист YouTube Music |
| `--update` | синхронизировать с целевым плейлистом |
| `--remove-missing` | удалить из цели ранее перенесённые лишние треки |
| `--cache-dir DIR`, `--no-cache`, `--refresh-cache`, `--reuse-cache` | управление кэшем поиска |
| `--decisions FILE`, `--refresh-decisions` | CSV ручных решений |
| `--no-review` | не создавать `review.html` |
| `--explain` | печатать компоненты оценки |
| `--progress` | прогресс-бар (нужен `tqdm`) |
| `--quiet` | не печатать каждый трек |
| `--delay` | пауза между поисковыми запросами, по умолчанию `0.3` с |
| `--proxy` | HTTP(S)-прокси |
| `--language`, `--location` | язык и регион ответов YouTube Music |
| `--config`, `--only` | TOML-конфигурация и выбор одной секции |
| `--json-summary FILE` | JSON-сводка прогона |
| `--log-file FILE` | дублировать вывод в файл |
| `--debug` | показывать traceback |

## Статусы и коды выхода

| Статус | Что значит |
| --- | --- |
| `matched` | уверенное совпадение; трек добавлен (или готов к добавлению) |
| `ambiguous` | похожие результаты; по умолчанию **не добавляется** |
| `not_found` | подходящий трек не найден или оценка ниже порога |
| `unavailable` | трек недоступен в Яндекс.Музыке |
| `error` | ошибка поиска, решения или добавления; причина в `note` |
| `duplicate` | тот же `video_id` уже занят другой позицией |
| `skipped` | исключено вручную через `decisions.csv` |

Коды выхода: `0` — успех; `1` — ошибка конфигурации/авторизации/фатальная
ошибка; `2` — прогон завершён, но есть `error` или неудачные добавления;
`130` — прервано с клавиатуры (частичный результат сохранён).

## Как работает сопоставление

- Названия очищаются от пометок `feat.`, `prod.`, `Remastered`, `Live`,
  `Radio Edit`, `Official Video`, времени в конце названия и т. п.
- Сравнение идёт по нормализованному тексту и транслитерации
  (`Кино` ↔ `Kino`, `Группа крови` ↔ `Gruppa Krovi`).
- Итоговая оценка: `0.55 × название + 0.30 × исполнитель +
  0.15 × длительность` (без длительности веса перераспределяются).
- Штрафы: кавер/караоке/колыбельная — ×0.7, live/remix/acoustic и другие
  версии — ×0.8, слишком далёкое название — ×0.7, другой исполнитель — ×0.7.
- Кандидаты с `isAvailable=false` отбрасываются.
- Повторы `video_id` добавляются один раз; вторая позиция получает `duplicate`.
- `ambiguous` ставится, когда два кандидата отличаются меньше чем на 0.05 и
  лучший результат ниже 0.9.

## Ограничения

- Обе библиотеки работают с неофициальными API и могут ломаться при изменениях
  сервисов. Соблюдайте их условия использования.
- Каталог YouTube Music зависит от региона и авторизации. Песни, которых нет в
  каталоге, останутся `not_found`; `--location` иногда помогает.
- Автоматическое сопоставление не идеально: проверяйте `ambiguous` и
  `not_found`, особенно для каверов, ремиксов и одноимённых песен.
- OAuth-токены и заголовки `browser.json` со временем истекают; повторите
  авторизацию.
- При больших плейлистах возможны ограничения частоты запросов: увеличьте
  `--delay` и перезапустите с `--resume`.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тесты не ходят в сеть: клиенты Яндекса и YouTube подменяются, проверяются
матчинг, штрафы, состояние, решения, отчёты, обработка ошибок записи и
офлайн-кэш.
